# AstrBot NovelAI Painter

面向 AstrBot 公共插件生态的 NovelAI 生图扩展。重点是可控、可审计、避免重复请求：固定命令、LLM 工具、权限策略、单任务请求上限、角色卡、参考图、表情包模式与 WebUI 管理均可配置。

## 主要能力

- NovelAI 官方后端：文生图、图生图、V5 / V4.5 / V4 / V3 官方模型下拉选择、Precise Reference / Character Reference / Style Reference；LLM 单人图可自动使用选中角色卡绑定的参考图。
- OpenAI / NewAPI 兼容后端：/v1/images/generations 与 /v1/images/edits。
- 入口四选一：全部禁用、仅固定命令、仅 LLM 工具、两者都启用；固定命令名可在 WebUI 修改，默认是 /nai。
- 私聊 / 群聊权限：所有人、仅管理员、白名单、禁用；管理员绕过白名单可单独控制。
- 严格安全上限：每条入站消息最多一个任务、最终最多发送一张图片；默认不重试。只有管理员主动启用时才会对明确的 429 限流执行最多两次重试。
- 消息去重：按消息 ID 或事件指纹做短窗口去重。
- 角色卡：区分 AI 自身人设、库中角色和无卡角色；默认保留精确标签与权重，由主模型根据剧情只增删发生变化的部分，同一对话后续画面沿用最近成功生成的外观。V4/V5 多人图使用独立角色正负提示词。
- WebUI 页面：连接测试、入口与权限、基础参数、角色卡、参考图上传、图生图参数、任务记录，均提供保存按钮和成功/失败反馈。
- 表情包模式：独立 WebUI 页面配置总开关、触发概率、冷却、上下文条数、判断模型、发送方式和专用角色卡；LLM 可提供情绪标签，插件结合上下文判断是否生成嘲笑、无奈、震惊等反应表情。
- 公共插件中性回复：不注入任何个人称谓、固定人格或个人标签；最终对话风格由 AstrBot 当前人设决定。

## 安装

在 AstrBot 插件市场安装，或执行：

    git clone https://github.com/zzz27578/astrbot_plugin_novelai_painter.git

安装后进入 AstrBot WebUI 的插件详情页，打开 NovelAI Painter 设置页面完成配置。2.6.1 要求 AstrBot >= 4.27.3，并使用该版本起提供的统一人设解析接口，确保会话强制人设、Conversation 人设和默认人设与 AstrBot 主 Agent 的选择结果一致。

## 命令

默认入口模式为“仅固定命令”，命令前缀为 /nai：

    /nai draw <画面描述>
    /nai self <画面描述>
    /nai card-draw <角色卡 ID> <画面描述>
    /nai img2img <画面描述>
    /nai reference character <画面描述>
    /nai reference style <画面描述>
    /nai reference both <画面描述>
    /nai card current
    /nai card list
    /nai card use <角色卡 ID 或完整名称>
    /nai card clear
    /nai model current
    /nai model list
    /nai model use <模型 ID 或别名>

只发送 `/nai` 或 `/nai help` 会列出全部可执行命令。`/nai <描述>` 旧格式默认兼容，可在 WebUI 关闭。参考图需要先在 WebUI 上传并绑定到角色卡；图生图优先使用绑定的参考图。固定命令成功时只发送图片，不追加一次 Agent 聊天回复。

从 2.5.0 开始，`/nai draw` 和旧格式 `/nai <描述>` 直接按描述作画，不再自动附加自身角色卡。`/nai self` 使用当前人设映射或默认卡；`/nai card-draw <ID>` 只在本次使用指定卡，不会修改人设绑定。`/nai img2img`、`/nai reference` 继续使用当前卡的绑定参考图。

`card use` 会优先修改当前 AstrBot 人设到角色卡的持久映射；会话未启用人设时修改默认角色卡。`card clear` 按相同作用域解除映射。`model use` 只允许切换 WebUI 列出的 NovelAI 官方模型，支持 `v5`、`v4.5`、`v4`、`v3` 等别名。帮助、查看、切换角色卡和切换模型都归入固定命令入口，并统一受 WebUI 的入口模式、私聊/群聊权限和白名单控制。

LLM 工具名称为 novelai_generate_image。只有在入口模式启用、用户通过权限检查，并且用户明确要求生成/绘制/修改图片时才会执行。

LLM 工具会先把图片直接发送到当前会话，再返回带有完成标记的工具结果，明确要求 Agent 停止调用工具并按当前 AstrBot 人设简短回复一次。只有本次选中单个角色卡且“LLM 自动应用绑定参考图”已开启时才可自动使用参考图；默认的剧情锚点模式还要求主模型确认参考图符合当前外观并设置 `use_reference=true`，避免参考图把旧衣服带回来。用户明确要求参考图操作时仍可使用 `img2img` / `reference`。

LLM 会收到当前自身卡的标识和已启用角色卡目录，再用工具的 `subjects` 分别指定绘画对象。默认剧情锚点模式会将卡的正负 Tag 与本对话上次成功绘画的外观提供给主模型，由主模型判断剧情变化并提交增删补丁。插件保留所有未修改的原词，不重新注入默认服饰，也不让整段外观改写丢失角色名、画师名或权重。没有角色卡时，LLM 可将已知角色名翻译为英文角色 Tag，并结合用户描述补充外貌；角色知识取决于所用 LLM，生图效果取决于图像模型。

例如“画你自己”使用 `source=self`；“画库中的某角色”使用 `source=card` 和其 `preset_id`；“画初音未来”使用 `source=custom`，无需创建新卡。“你和初音一起合影”可混用两种来源，每人一项。画风景、物品或完整自由描述时使用空数组，不会默认添加人设。

`subjects` 为 JSON 数组字符串，最多 6 项，例如：

```json
[
  {"source": "self", "prompt": "smiling", "use_reference": false},
  {"source": "card", "preset_id": "other-card-id", "prompt": "standing"},
  {"source": "custom", "prompt": "hatsune miku, aqua hair, twintails, singing"}
]
```

顶层 `prompt` 描述共享场景、构图、人数和画风。剧情锚点模式下，已绑定卡的 `self/card` 自动沿用该对话上次成功生成的外观，首次原样使用角色卡。没有变化时只需 `source` 和当次动作表情 `prompt`，不能自行改写精确标签。`custom` 仍在自己的 `prompt` 中完整描述角色。每人的内容分别整理，避免把 A 的服饰套给 B。

只有剧情实际改变外观时，使用 `appearance_patch` 提交改动，例如当前正向含 `black bodysuit`、负面含 `white dress`，换白裙用：

```json
[{"source":"self","appearance_patch":{"remove":["black bodysuit"],"add":["white dress"],"negative_remove":["white dress"]},"prompt":"smiling"}]
```

`remove/add` 分别为正向标签删除/加入数组，`negative_remove/negative_add` 为负面词的对应数组；不受影响的内容原样保留。删除必须复制当前外观中的完整标签及权重，含多个词的完整权重组作为一项。例如 `{forehead jewel}` 不能写成 `forehead jewel`；`{{yellow split skirt, red boots}}` 应整组替换。不存在的删除项、无效补丁和超长结果在请求生图前报错，不更新缓存。只恢复默认衣服时也使用服饰补丁；明确恢复整张默认卡才使用 `{"reset":true}`，可同时叠加增删项。

2.6.0 的整段外观重写容易让模型丢失精确角色名、画师名、服饰名和原有权重。2.6.1 起，绑定卡的旧 `appearance_prompt/negative_prompt` 整段字段会被忽略并记录警告，使用原卡或当前外观继续生成；剧情变化需使用补丁。无卡角色仍可使用这两个字段描述完整外观。

V4/V5 使用官方独立角色提示词及独立负面词；V3 与 OpenAI 兼容后端使用逐角色描述，隔离效果由上游模型决定，多人图推荐 V4/V5。多人图不自动使用角色卡参考图，且拒绝多人 `reference` / `img2img`，避免把单人参考应用到整张图。省略 `subjects` 仅兼容明确的单人自画像，其余请求不套卡；显式 `[]` 始终不套卡。

## 2.6.1 精确保留原词与剧情连续性

默认 `llm_card_mode=context`，在设置页“角色卡 → LLM 角色卡使用方式”选择。主模型根据“最新明确要求 → 当前剧情 → 上次成功绘画外观 → 卡默认值”判断变化，通过补丁调整对应标签。未发生变化的身份、画风、服饰、原生权重和负面词保持原样，新对话首次绘画也无需让模型重写卡词。默认衣服不会因下一轮没再提换装就强行恢复。不额外请求判断模型。

例如先说“换上白裙画一张”，下一轮只说“走到窗边再画一张”，仍会沿用白裙；用户说“换回默认衣服”或剧情明确换回时，再由主模型替换对应服饰词。原角色卡始终不会被改写。

外观缓存只在普通 LLM 生图成功后更新，失败和重复请求不更新；按 UMO、当前对话 ID 和角色卡 ID 分别隔离，最多保留 256 项。编辑卡锚点后旧缓存失效。缓存仅在内存，重载后不保留，新对话不沿用旧对话的衣服；主模型仍可依据当前可见聊天用补丁恢复剧情变化。无法识别当前对话时只使用本次参数，不共享缓存。缓存用于补充上下文，剧情理解与最终画面仍取决于模型。

`llm_card_mode=strict` 保留旧版固定特征过滤和本轮覆盖逻辑，适合需要每次回到固定造型的使用方式。角色卡的锁定、强度控件仅约束严格模式及固定命令；普通剧情锚点模式保留原生权重并应用主模型的精确补丁。固定命令和表情包专用卡不读取或更新普通绘画的剧情外观缓存。

验证说明见 [UPDATE_REPORT_2.6.1.md](UPDATE_REPORT_2.6.1.md)，此前外观连续性设计见 [2.6.0 更新说明](UPDATE_REPORT_2.6.0.md)。

## WebUI 配置

页面中的设置分为：

1. 连接与模型：NovelAI 官方模型下拉列表、OpenAI/NewAPI 兼容模式、地址、密钥、鉴权请求头/前缀、尺寸、Steps、Scale、Sampler、负面提示词。
2. 入口与权限：命令 / LLM 工具开关、私聊和群聊策略、白名单、管理员绕过、排队提示、429 提示、错误通知、去重窗口、临时文件清理，以及三档 429 自动重试策略。
3. 角色卡：创建、编辑、删除、启用/禁用、绑定 AstrBot 人设 ID，保存统一的角色卡正向 Tag、角色卡负面 Tag、一致性保护开关和锚定强度。
4. 参考图与图生图：总开关、上传、删除、绑定、图生图 Strength/Noise、颜色校正、Precise Reference Strength/Fidelity。
5. 任务记录：查看和删除本次运行期间的最近任务状态，可删除单条或清空全部；不保存完整提示词和密钥。
6. 表情包模式：总开关、概率、冷却、判断上下文、判断模型、超时、图片尺寸、通用提示词、判断规则、发送方式和表情包专用角色卡。

表情包模式默认关闭。开启后，每次普通 LLM 回复先按配置概率抽样，再由判断模型返回 `send`、`emotion` 和视觉提示。判断模型返回不发送、概率未命中、请求超时或表情包生图失败时，原文字回复不受影响。发送方式可以选择文字回复后发送，或与最终文字结果合并为同一条消息链；后一种模式会自动关闭本次回复的流式输出，以保证文字和图片一起发出。

点击顶部或底部“保存配置”后会立即写入插件配置，并通过页面提示保存结果。保存失败也会返回可读的中文错误，不依赖 Dashboard 的原始错误响应。

## 2.4.0 表情包模式

- 新增独立的“表情包模式” WebUI 页面，提供总开关、触发概率、会话冷却、上下文条数、判断模型、判断超时、图片尺寸、发送方式、情绪标签工具和自动参考图等配置。
- 普通 LLM 回复完成后，插件按概率抽样，再将最近上下文、最终回复、LLM 情绪标签和表情包专用角色卡交给判断模型；模型返回 `send`、情绪和英文视觉提示后，复用现有生图后端、角色卡 Tag、负面 Tag、参考图、重试、去重和临时文件清理逻辑。
- 支持“文字回复后发送”和“与文字同一气泡”两种方式。同一气泡模式会为本次会话关闭流式输出，将最终文字与图片合并为一条消息链。
- 判断模型不发送、概率未命中、冷却中、判断超时或生图失败时，原文字回复保持不变；表情包模式默认关闭。
- 新增 `novelai_set_emotion` 内部工具；只有表情包总开关和“允许 LLM 提供情绪标签”同时开启时，工具才会暴露给主 LLM，允许其提供“嘲笑、无奈、震惊”等简短情绪标签和视觉提示，元数据不会出现在用户正文中。

完整验证说明见 [UPDATE_REPORT_2.4.0.md](UPDATE_REPORT_2.4.0.md)。

## 2.3.0 重构

- 将“画风提示词 + 人物提示词”合并为单一“角色卡正向 Tag”，保留独立“角色卡负面 Tag”，降低两组锚点互相竞争和 WebUI 配置看似绑定、运行时却未统一消费的问题。
- LLM 只负责翻译当前动作、姿势、表情、构图、场景和用户明确修改项；插件在后端解析当前 AstrBot 人设绑定的角色卡，先放入加权角色卡 Tag，再追加 LLM Tag。
- 角色卡负面 Tag 与全局负面提示词共同进入 NovelAI 官方 payload；OpenAI 兼容后端会将两者转换为明确的 Avoid 指令。
- 默认锁定人物主体与画风。LLM 自行补写但用户没有要求的发色、眼睛、种族、服装、主体和画风 Tag 会被过滤；用户明确修改的类别仅在本次生成中覆盖，不持久化回角色卡。
- 修复 AstrBot 4.27.3+ 中工具返回 `None` 导致 Agent 直接结束、图片发送后没有人设回复的问题。自然语言工具成功或失败后都会返回最终状态，要求 Agent 停止工具调用并简短收尾；多层去重仍保证同一消息最多建立一个后端任务并发送一次图片。
- `/nai` 命令与 LLM 工具分离：固定命令成功后只发图，自然语言工具成功后允许当前人设回复一句。
- 旧角色卡中的 `style_prompt`、`character_prompt`、两组锁定和强度字段会在启动时原子迁移到新结构，正向内容和负面 Tag 均保留。

完整验证与兼容说明见 [UPDATE_REPORT_2.3.0.md](UPDATE_REPORT_2.3.0.md)。

## 2.1.3 修复

- LLM 工具描述改为只整理本次动作、姿势、表情、构图和场景变化，不再让模型重写预设中的人物或画风内容。
- 严格按“每条入站消息最多一张图片”去重：即使 LLM 多次改写提示词、命令与工具重复触发或操作类型不同，也只允许一次任务；发送阶段再增加 Job ID 防重复保护。服务端即使返回多张图片，也只读取第一张。
- WebUI 增加三档 429 重试策略：不重试、仅 429 重试 1 次、仅 429 重试 2 次，并开放等待时间与重试提示开关。网络超时、连接中断、5xx 和其他不确定错误始终不自动重试，避免重复生成或重复扣费。

## 安全行为

- 自动重试默认关闭。只有明确的 HTTP 429 可按 WebUI 选择重试一至两次；网络超时、连接中断、5xx、认证和额度错误不会自动重试。
- images_per_request 始终强制为 1；正常任务只发送一次 API 请求，启用 429 重试后总尝试次数硬限制为 2 或 3，且成功后立即停止。
- 错误通知默认只发送最终结果，不发送原始异常、Token、路径或代理细节。
- 临时图片和参考图存储在 AstrBot 插件数据目录，不使用写死的系统绝对路径。
- 参考图上传限制为 PNG/JPEG/WebP，单文件不超过 12MB，服务端重新命名并校验路径。

## 开发说明

插件配置 Schema 位于 _conf_schema.json，复杂页面位于 pages/settings/，插件运行数据位于 AstrBot 的插件数据目录。升级旧版本时，缺少的新配置项会自动补齐；旧画风/人物预设会迁移为角色卡，原有负面 Tag、api_token、base_url、模型和生图参数仍可继续使用。
