# AstrBot NovelAI Painter

面向 AstrBot 公共插件生态的 NovelAI 生图扩展。重点是可控、可审计、避免重复请求：固定命令、LLM 工具、权限策略、单任务请求上限、角色卡、参考图、表情包模式与 WebUI 管理均可配置。

## 主要能力

- NovelAI 官方后端：文生图、图生图、V5 / V4.5 / V4 / V3 官方模型下拉选择、Precise Reference / Character Reference / Style Reference；LLM 单人图可自动使用选中角色卡绑定的参考图。
- OpenAI / NewAPI 兼容后端：/v1/images/generations 与 /v1/images/edits。
- 入口四选一：全部禁用、仅固定命令、仅 LLM 工具、两者都启用；暗号 `n` 触发聊天加绘图，`/n [自然语言要求]` 只调用绘图 LLM，`/nai <Tag>` 直接提交图片服务。
- 私聊 / 群聊权限：所有人、仅管理员、白名单、禁用；管理员绕过白名单可单独控制。
- 严格安全上限：每条入站消息最多一个任务、最终最多发送一张图片；默认不重试。只有管理员主动启用时才会对明确的 429 限流执行最多两次重试。
- 消息去重：按消息 ID 或事件指纹做短窗口去重。
- 角色卡：区分 AI 自身人设、库中角色和无卡角色；身份锚点、默认完整服饰和画风分层，保留精确标签与权重；主模型区分本图换装和剧情换装，服饰整体替换，避免叠加。V4/V5 多人图使用独立角色正负提示词。
- 可选独立绘图 LLM：接收用户本轮原话、主模型完整回复、限定上下文和角色卡，回复发送后再写 Tag；可选读取本轮附图和有效的上一张成图。`/n` 也可直接由它理解中文要求并出图。
- WebUI 页面：连接测试、入口与权限、基础参数、角色卡、参考图上传、图生图参数、任务记录，均提供保存按钮和成功/失败反馈。
- 表情包模式：独立 WebUI 页面配置总开关、触发概率、冷却、上下文条数、判断模型、发送方式和专用角色卡；LLM 可提供情绪标签，插件结合上下文判断是否生成嘲笑、无奈、震惊等反应表情。
- 公共插件中性回复：不注入任何个人称谓、固定人格或个人标签；最终对话风格由 AstrBot 当前人设决定。

## 安装

在 AstrBot 插件市场安装，或执行：

    git clone https://github.com/zzz27578/astrbot_plugin_novelai_painter.git

安装后进入 AstrBot WebUI 的插件详情页，打开 NovelAI Painter 设置页面完成配置。2.10.4 要求 AstrBot >= 4.27.3，使用统一人设解析接口和不保存到历史的临时消息内容；会话强制人设、Conversation 人设和默认人设与 AstrBot 主 Agent 的选择结果一致。

## 2.10.4 绘图入口与独立 LLM

先在 AstrBot 中配置一个聊天模型 Provider，再到插件页面“连接与模型 → 独立绘图 LLM”填写或选择其 **Provider ID**。它仅用于暗号 `n` 和 `/n`，图片仍由 NovelAI / 兼容图片服务生成。**普通工具调用始终由主模型写完整参数直接出图，配置独立模型不再自动转述。** 留空关闭暗号和 `/n`，主模型工具不受影响。

| 使用方式 | 主模型 | 绘图 LLM |
|---|---|---|
| `n`、`n换白裙坐在窗前`、`换白裙坐在窗前n` | 正常聊天；无需写 Tag 或转交意图 | 回复发送后直接读取原话、完整回复和当前上下文出图 |
| `/n`、`/n 换白裙坐在窗前` | 不调用，不追加文字回复 | 立即读取当前上下文并出图 |
| 自然语言告诉主模型画图 | 编写完整 Tag 与人物参数，调用 `novelai_generate_image` 直接出图 | 不调用 |
| `/nai <Tag>` | 不调用 | 不调用，直接提交图片服务 |

暗号默认 `n`，可在 WebUI 修改或留空关闭。支持独立发送、消息首尾、紧贴中文、大小写；英文单词 `night`、`sun` 和 URL 尾部 `/n` 不触发。`n` 与 `/n` 归入固定命令入口权限，配置“仅固定命令”即可使用；普通工具请求需要开放 LLM 工具入口。修复了旧版两种“仅…”模式与实际判断值不一致的问题。未带暗号、也未调用工具的聊天不自动配图。

双线入口在 await 前独立抢占本条绘图请求，主模型随后误调工具也不会重复生成。主模型照常回复，图片在回复发送后生成，普通和流式回复均支持。主模型没有正常完成回复时不会提前开始双线绘图，可用 `/n` 单独提交。

暗号或 `/n` 的独立模型直接收到用户原文，包含换装、人物、姿势和改图要求，**不依赖主模型转述**。用户明确要求优先；“画当前剧情”读取当前剧情，“修改上一张，其他不变”以最近成功方案为基础只改指定项，新图则按新要求组织。内置[专用绘图技能](skills/novelai-painter/references/drawing-planner.md)随请求加载；有卡角色仍由后端保留精确角色名、原生权重、画师名和负面词，多人分别选卡，无卡人物无需建卡。独立规划的换装只作用于本图，不写成剧情事实。

两种 LLM 使用同一来源和当前对话 ID，不为绘图新建聊天。默认读取同一会话最近 12 条 user/assistant 文本消息，每条最多 2000 字符，可配置为 0–30 条。用户本轮原话与本轮完整回复另行提供；0 条上下文仍保留它们。`/n` 没有本轮主模型回复，读取已有的当前对话。最近一次成功绘图的用户要求和发送记录临时提供给下一轮主模型，避免它完全不知道用户刚改过图；记录不作为新的绘图请求或剧情事实。绘图 Tag 不整段写入主聊天历史，也不读历史工具参数或聊天系统人设。

“读取附图和最近成图”默认关闭。开启后需选择有视觉能力的模型，会向该 Provider 发送最多两张本轮附图和一张有效的上一张成图；附图用于理解，不自动作为图生图底图。最近成功发送的独立绘图方案按会话保留最多 30 分钟，最多 8 个会话；图片仅在开启视觉时复制保留，每张上限 8 MiB。reset/new/switch、历史改写或角色卡变更会使旧参考失效，插件重载后不恢复。没有可验证的当前对话时，不读取跨轮绘图缓存。

`/n 换白裙坐在窗前，保留耳朵和发型` 立即交给独立模型，成功只发图片。单独 `/n` 表示画当前场景；未配置独立模型时给出配置提示，不再把中文直接发给 NAI。原来的直接 Tag 入口移为 `/nai white dress, sitting by a window`，沿用当前绑定/默认卡，不调用任一 LLM；`/nai draw <Tag>` 仍为不套卡的自由绘画。

输出协议默认“自动”：AstrBot OpenAI 兼容 Provider 使用请求内的 `novelai_generate_image` 参数工具，复用主绘图工具的 prompt/subjects/style 字段定义，tool_choice 与主 Agent 一样使用 auto。插件只读取这一次参数提交，校验后出图，不运行聊天工具循环。旧 submit_drawing_plan 回包仍可解析。显式选择 JSON 模式时，OpenAI Chat Completions 兼容请求携带 response_format=json_object；不支持会明确报错，不静默切换协议重发。其他 Provider 仍按技能要求返回 JSON。

2.10.4 重新整理独立调用：“绘图 LLM 调用方式”自动模式跟随主聊天的流式设置；取不到设置时，OpenAI 兼容 Provider 使用流式。可显式选择流式或非流式。JSON 和参数工具均支持，流式内容仅在插件内部接收，等完整最终结果并校验后才请求图片服务。连接中断或缺失最终结果会明确报错，不用部分 JSON 出图，也不自动切换路径再发一遍。

新增“绘图 LLM 推理强度”和“输出 Token 预算”：默认继承/0，不覆盖 Provider；选择低/中/高或非 0 预算时，仅覆盖本次 OpenAI 兼容绘图请求的 `reasoning_effort` / `max_completion_tokens`。使用独立配置副本传入适配器，避免 AstrBot 丢弃任意 kwargs，也不改变主聊天配置。上游需支持这些字段。Token 预算可能包含隐藏推理；截断会停止，不能靠再跑一次相同预算修复。

解析清理思考块、围栏和说明文字中的唯一完整 JSON，也识别明确命名的工具参数包装、旧式 subjects 数组字符串，以及冗余的 `operation=generate` / 空 reference_type；不丢弃未知的语义字段或改写 Tag 权重。仍无效时默认反馈错误和前次输出，最多纠正一次。**首次调用与纠正共用总超时预算，默认 60 秒，可调 5–180 秒**，第二次仅使用剩余时间，少于 3 秒不再发起纠正。参数通过前不请求图片服务；拒绝、截断、超时和网络错误停止，不回退主模型 Tag。图片后端的有限 429/503 重试与此独立。

绘图输入保留用户原话、完整本轮回复及配置范围内的历史。历史以原生 user/assistant 消息传入，本轮要求直接作为最后一条用户消息；角色目录和上一张方案独立标记为辅助素材，不再把所有对话压成一个素材 JSON。精简系统技能，角色卡原始身份、画风、权重和负面词仍由后端应用；主模型直接出图的成功方案仍可用于后续 `/n` 改图。

日志用 request_id 关联主聊天、等待回复、准备素材、调用 Provider、收到回包、校验和图片任务。2.10.2 增加 Provider/模型及接口指纹、允许公开的推理/长度参数、SDK 重试配置、技能与工具 schema 大小、各输入字段长度、上下文来源、当前/上张图片来源，以及上游提供的模型名、结束原因、Token/缓存/推理用量和服务请求 ID。默认不记录正文、图片地址或密钥；开启“记录绘图回包预览”才显示最多 2000 字符绘图返回。快照保留本轮最近请求与结果、最多 24 个阶段，避免发图覆盖规划回包。

每等待 Provider 30 秒记录一次 `provider_wait`；`received.provider_ms` 单独计 Provider 等待，`response.validation_ms` 计本地校验。2.10.3 流式调用增加首段文字/推理的可见时间、累计长度及最终结果时间，并记录覆盖参数、原始正文长度和原始推理字段长度，帮助判断短 JSON 却报告数千输出 Token 的原因。AstrBot 可能只在流结束提供工具参数，此时不虚报首 Token 时间。`request` 是调用 Provider 的时点，包含后续 SDK 准备、重试及上游等待；不代表 HTTP 已到服务器。主模型 `hook_elapsed_ms` 可能包含多轮工具和生图，不能当单次模型耗时。切换 Provider 或对话会取消旧任务。实际 Grok 速度仍需服务实测确认。

2.10.4 为 OpenAI 兼容绘图请求创建局部 SDK 客户端副本，关闭 SDK 自带重试（max_retries=0），不改主模型的配置、鉴权或连接池。AstrBot 自身的 Key/兼容性回退仍可能追加请求，每次实际 HTTP send 都计数。新增 http_request/http_headers/http_first_body/http_first_content/http_first_tool_arguments/http_end/http_error，记录序列化请求的字段、消息角色、格式类型、响应头等待、首字节、正文/工具参数长度、状态码和服务器请求 ID；支持 httpx/httpx2 和压缩回包，network_events 记录底层提供的连接/TLS/请求头及响应头阶段。超时保留已有指标，调试开启时保留最多 2000 字符的绘图输出预览，不记录推理正文。HTTP send 时点包含本地连接池与网络等待，不能据此测出上游内部排队或隐藏推理。

对照操作见 [延迟诊断测试步骤](DIAGNOSTIC_TEST_GUIDE.md)。验证及实现说明见 [2.10.4 更新说明](UPDATE_REPORT_2.10.4.md)，前版见 [2.10.3 更新说明](UPDATE_REPORT_2.10.3.md)。

## 命令

默认入口模式为“仅固定命令”，命令前缀为 /nai：

    n
    n<自然语言要求>
    /n [自然语言要求]
    /nai <Tag>
    /nai draw <画面描述>
    /nai self <画面描述>
    /nai card-draw <角色卡 ID> <画面描述>
    /nai img2img <画面描述>
    /nai reference character <画面描述>
    /nai reference style <画面描述>
    /nai reference both <画面描述>
    /nai card current
    /nai card list
    /nai card use <角色卡 ID 或完整名称>
    /nai card clear
    /nai model current
    /nai model list
    /nai model use <模型 ID 或别名>

只发送 `/nai` 或 `/nai help` 会列出全部可执行命令。`/nai <Tag>` 直接入口默认启用，可在 WebUI 关闭。参考图需要先在 WebUI 上传并绑定到角色卡；图生图优先使用绑定的参考图。固定命令成功时只发送图片，不追加一次 Agent 聊天回复。

`/n` 固定为自然语言绘图入口，无需手写 Tag，也不调用主聊天模型；必须配置独立绘图 LLM。不自动续用上一张图或附图作为图生图底图，遵守固定命令入口、权限、去重和生命周期校验。`/nai <Tag>` 使用绑定/默认卡直接请求图片服务，无卡则按原文；本图修改不保存为剧情换装。`/n` 与 `/nai` 保留为固定入口，其他管理命令还可使用自定义前缀。

`/nai draw` 不附加自身角色卡。`/nai self` 使用当前人设映射或默认卡；`/nai card-draw <ID>` 只在本次使用指定卡，不修改绑定。`/nai img2img`、`/nai reference` 使用当前卡的绑定参考图。2.10.0 起 `/nai <Tag>` 承接旧 `/n` 的绑定卡直接提交行为。

`card use` 会优先修改当前 AstrBot 人设到角色卡的持久映射；会话未启用人设时修改默认角色卡。`card clear` 按相同作用域解除映射。`model use` 只允许切换 WebUI 列出的 NovelAI 官方模型，支持 `v5`、`v4.5`、`v4`、`v3` 等别名。帮助、查看、切换角色卡和切换模型都归入固定命令入口，并统一受 WebUI 的入口模式、私聊/群聊权限和白名单控制。

LLM 工具名称为 novelai_generate_image。只有在入口模式启用、用户通过权限检查，并且用户明确要求生成/绘制/修改图片时才会执行。

主模型工具会先发送图片，再返回完成标记及本次画面摘要，要求本条消息不再重复绘图；无论是否配置独立模型，均不转述。出图后按当前对话自然回应，摘要只是请求内容，并非对成图的视觉检查。仅暗号本条绘图已排队时，主模型误调工具会返回重复拦截，继续正常聊天。只有选中单个卡且开启“LLM 自动应用绑定参考图”时才可自动使用参考图；剧情锚点模式还要求 `use_reference=true`，避免旧服饰回流。用户明确要求参考图操作时仍可用 `img2img` / `reference`。

卡目录与服饰状态通过 AstrBot 临时消息内容传给本轮 LLM，不再追加到系统提示词，也不保存进聊天历史。仅提供自身卡标识、已启用卡的名称/说明、默认服饰和经当前历史验证的剧情服饰；精确身份与画风标签仍由插件读取卡后应用，避免模型反复抄写卡词。目录是工具素材，服饰状态不是新剧情；下一轮刷新临时数据时不改写人设。画其他角色无需绑定或创建角色卡；角色知识取决于所用 LLM，成图取决于图像模型。

`subjects` 是**原生 JSON 数组**，最多 6 人，每人一项：

```json
{
  "prompt": "2girls, park, full body, afternoon",
  "subjects": [
    {"source": "self", "prompt": "smiling"},
    {"source": "custom", "prompt": "hatsune miku, girl, aqua hair, twintails, aqua eyes, black sleeveless shirt, detached sleeves, black skirt"}
  ]
}
```

- `self`：只解析 AI 当前人设对应的卡，未绑定时可按当前聊天描述自身外貌。
- `card`：用 `preset_id`（卡 ID 或完整名称）选择库中某张卡，完全不改变聊天身份或绑定。
- `custom`：可在自己的 `prompt` 或 `appearance_prompt` 写角色名/外貌，无需建卡；描述已在顶层 `prompt` 时可省略人物项的 `prompt`。空的 `appearance_prompt` 按省略处理。
- 无卡绘画、风景和物品用 `subjects=[]`。用户明确要求画自己或使用内置/绑定角色卡时，模型遗漏选择或误传空数组会补选对应卡；指定卡名优先，否则使用当前绑定/默认卡，未绑定时仅有一张可用卡才直接选用。不能唯一确定的卡请求交给模型按目录修正，避免静默生成无卡图片。普通其他角色、多人和只借用卡画风的请求不会通过该兜底套上自身卡。旧版有效的数组字符串仍可读取，新工具结构统一引导原生数组。

## 2.7.2 选卡兜底与分层角色卡

默认 `llm_card_mode=context`，不额外调用判断模型。每个有卡角色按“身份锚点＋一套当前完整服饰＋画风”组成，顶层 `prompt` 可以是完整画面，也可以只写共享场景；各角色 `prompt` 可含动作、表情和服饰。角色名、画师名和原生权重由插件直接保留，绑定卡的旧整段 `appearance_prompt/negative_prompt` 不会覆盖它们。

`outfit` **整体替换**当前服饰层，必须包含本次所有衣服、鞋和需要保留的服饰配件；空字符串表示明确无服饰。推荐用该字段表达明确换装，但普通 `prompt` 提及服饰不会拒绝生成。检测到普通描述中已有服饰时保留原文，并停止额外追加缓存/默认服饰；未提供服饰描述时才先用经当前历史验证的剧情服饰，再用卡默认服饰。兼容识别只是补充措施，不会把普通画面描述写入剧情状态，也不会猜测共享服饰归属于哪一个角色；多人建议各自描述放在各自项。

仅想象本图换装（默认 `state_scope=image`）：

```json
{"prompt":"bedroom, full body", "subjects":[{"source":"self", "outfit":"white dress, sandals", "prompt":"smiling"}]}
```

当前剧情中实际已经换装，后续画面应延续：

```json
{"prompt":"window, sunlight", "subjects":[{"source":"self", "outfit":"white dress, sandals", "state_scope":"story", "prompt":"standing"}]}
```

主模型根据最新要求和**当前可见剧情**判断 `image/story`，绘画设想本身不证明剧情已经换装。只保存明确标为 `story` 的完整服饰，不保存整段生成提示词；图像服务失败不会把剧情实际换装撤销。本图服饰不会写回原卡或剧情。剧情早已换装但尚未绘图、或插件重载后，模型可从当前聊天重新提交 `outfit` 和 `state_scope=story`。

用户明确要求更改本图画风时用顶层 `style` 完整替换；常规用卡画图省略它，保留卡内精确画师名及权重。剧情模式下，模型在用户没有要求改画风时自行填写的 `style` 会被忽略，不会抹掉原卡画风；无卡图不受此保护限制。身份锚点由角色卡编辑器维护。卡负面词原样保留，仅剔除与当前服饰完全匹配的单个禁止标签；全局负面词始终生效，复杂语义冲突仍应在卡或全局设置中检查。

剧情服饰在内存按会话来源、对话 ID 和角色卡 ID 隔离，最多 256 项。读取当前真实历史并检查产生状态的用户轮次是否仍在其中；成功 reset/new/switch 时通过 AstrBot 的生命周期标记清除状态，历史被清空/改写、卡被编辑时也会失效。不能读取或识别当前对话时不使用共享缓存。排队中的旧任务在发请求前再次校验对话，生成过程中重置则不向新对话发送旧图；已发出的服务请求仍可能产生服务费用。

旧 `appearance_patch` 增删补丁已停用，会在发出图片请求前返回可修正错误，要求改传完整 `outfit`。参数错误允许一次纠正；任务通过验证并被接受后，同一消息仍只能生成一张图。参考图默认不启用，模型确认参考图符合当前服饰时才 `use_reference=true`；多人图拒绝全图 `reference/img2img`。

V4/V5 使用官方独立角色正负提示词，人物槽中的独立 `1girl/1boy` 转为 `girl/boy` 并去掉 `solo`，人数保留在场景层。V3 与兼容后端使用逐角色描述，隔离效果由上游模型决定。`llm_card_mode=strict` 保留旧版过滤和本轮覆盖，在各角色 `prompt` 写本次明确修改；分层换装字段用于剧情模式。`/n` 在剧情模式下可读取已确认服饰，但只生成本图；其他固定命令和表情包使用原有规则，不读取或更新普通生图的剧情状态。

### 旧卡迁移

升级时保留完整原始正向词，同时一次性提出身份、服饰、画风分组，并在数据目录保存 `presets.before-layers.json` 备份。角色卡页标记“待检查分层”，可展开原文对照，检查后保存即可。迁移按关键词辅助分类，**不能保证任意卡自动分类正确**：未知服饰词、画师名，以及混合身份/服饰的权重组需要手动调整。运行时不逐词删除原描述；普通服饰描述的兼容识别仅用于停止额外追加缺省服饰。

例如精灵卡保留 `{{elf (isekai ojisan)}}`、`{forehead jewel}` 在身份层，`sleeveless black bodysuit, yellow split skirt, red boots` 放服饰层，`{atelier pontdarc}` 等放画风层。模板占位文字从绘图层移除，原文仍保留。

插件自带 [绘画技能说明](skills/novelai-painter/SKILL.md)，AstrBot 会发现插件 skills。若自行安装过旧版 NAI skill 或在人设中写了“subjects 必须是字符串”“增删补丁”“强制合并所有角色卡”等旧规则，请同步移除这些冲突指令。

## WebUI 配置

页面中的设置分为：

1. 连接与模型：NovelAI 官方模型下拉列表、OpenAI/NewAPI 兼容模式、地址、密钥、鉴权请求头/前缀、尺寸、Steps、Scale、Sampler、负面提示词，以及独立绘图 LLM Provider、上下文条数、超时、视觉开关与绘图偏好。
2. 入口与权限：命令 / LLM 工具开关、私聊和群聊策略、白名单、管理员绕过、排队提示、429 提示、错误通知、去重窗口、临时文件清理，以及三档 429 自动重试策略。
3. 角色卡：创建、编辑、删除、启用/禁用、绑定 AstrBot 人设 ID，分别编辑身份锚点、默认服饰、画风和负面 Tag；旧卡可对照迁移前原文，一致性保护与锚定强度用于严格模式及固定命令。
4. 参考图与图生图：总开关、上传、删除、绑定、图生图 Strength/Noise、颜色校正、Precise Reference Strength/Fidelity。
5. 任务记录：查看和删除本次运行期间的最近任务状态，可删除单条或清空全部；可查看各会话最近一次请求的最终提示词、角色槽及服饰来源快照，最多 20 份，仅驻留内存，不含密钥和图片。
6. 表情包模式：总开关、概率、冷却、判断上下文、判断模型、超时、图片尺寸、通用提示词、判断规则、发送方式和表情包专用角色卡。

表情包模式默认关闭。开启后，每次普通 LLM 回复先按配置概率抽样，再由判断模型返回 `send`、`emotion` 和视觉提示。判断模型返回不发送、概率未命中、请求超时或表情包生图失败时，原文字回复不受影响。发送方式可以选择文字回复后发送，或与最终文字结果合并为同一条消息链；后一种模式会自动关闭本次回复的流式输出，以保证文字和图片一起发出。

点击顶部或底部“保存配置”后会立即写入插件配置，并通过页面提示保存结果。保存失败也会返回可读的中文错误，不依赖 Dashboard 的原始错误响应。

## 安全行为

- 自动重试默认关闭。HTTP 429 可选择额外一至两次重试；HTTP 503 可独立配置额外 0–3 次。网络超时、连接中断、其他 5xx、认证和额度错误不自动重试。503 重发可能产生重复计费。
- images_per_request 始终强制为 1；图片 API 总尝试上限为首次 1 次 + 429 重试额度 + 503 重试额度，最大 6 次，两类错误分别计数，成功立即停止且只发送一张图。重试不重跑绘图 LLM，等待时释放全局通道，遵守 Retry-After 与会话失效检查。
- 错误通知默认只发送最终结果，不发送原始异常、Token、路径或代理细节。
- 临时图片和参考图存储在 AstrBot 插件数据目录，不使用写死的系统绝对路径。
- 参考图上传限制为 PNG/JPEG/WebP，单文件不超过 12MB，服务端重新命名并校验路径。
